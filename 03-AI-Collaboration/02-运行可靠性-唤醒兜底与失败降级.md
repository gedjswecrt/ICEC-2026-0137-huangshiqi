# 02 · 运行可靠性：它会不会自己醒、有没有网、网断了怎么办

- **时间**：2026-11-15 01:50 配置，07:30 实测
- **所属**：阶段二 · 项目四「每日校园早报」
- **证据**：`telemetry_20261115.jsonl` 中 `2026-11-15T07:30:03 · v0.2 · 0 报错`；`output/早报_2026-11-15.html` 修改时间 07:30

## 背景

考核要求「连续 7 天运行日志」。我的作息是凌晨两三点睡、早上起不来，所以整套自动化必须回答三个问题：

1. 电脑在睡眠中，7:30 会自己醒过来跑吗？
2. 醒了之后没网怎么办？
3. 万一某天真的没跑成，那次记录就永远丢了吗？

## 我的提问

> 我可能起不来这么早，电脑睡眠它可以运行吗？可是睡眠好像就会断网。

## AI 给的方案

三层，各自解决一个问题：

**第一层：怎么醒** —— 计划任务开 `WakeToRun = true`，允许任务唤醒电脑。现代待机机型大多支持，但不保证。

**第二层：醒来有没有网** —— 程序不是「在睡眠里偷偷跑」，而是被唤醒后才执行；唤醒时 Windows 会重连 Wi-Fi，而程序第一步读本地文件就要一两秒，等它请求天气 API 时网络已恢复。

**第三层：网断了怎么办** —— 天气接口包在独立异常处理里：失败就记一条 ❌ 然后继续，课程、DDL、HTML 渲染、日志写入照常完成。

另外配 `StartWhenAvailable = true` 作兜底：到点没跑成，下次开机立刻补跑。

## 我的判断

三层全上，但明确一条：**兜底机制绝不删**。哪怕唤醒每次都成功，也不能假设它永远成功——合盖、低电量、系统更新都可能让它失效。

同时要求天气失败必须**如实记为错误**，不能悄悄降级成「暂无数据」，否则看日志会误判当天一切正常。

## 验证

- **07:30:03**，我完全在睡觉，日志新增一条 `v0.2 · 0 报错`，`早报_2026-11-15.html` 修改时间正是 07:30 → 唤醒 → 联网 → 执行 → 写日志，整条链路实测通过
- 凌晨 01:25 曾发生主备两个天气源**同时**超时（`wttr.in: [SSL: UNEXPECTED_EOF_WHILE_READING]`），当天早报照样生成，只是天气板块缺失、日志记了一条 ❌ → 降级设计生效

## 复盘

自动化任务的可信度不来自「我配好了」，而来自「日志里有那一条」。
从这次起，每天检查一次日志时间戳成为固定动作，这本身也是 7 天连续运行数据的由来。
