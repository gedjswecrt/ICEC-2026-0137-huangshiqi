# 迭代 2：v0.2 → v0.3（2026-11-16）

## 改动依据（两条，均有留痕）

**依据一 · 运行日志**：`process_logs/telemetry_20261116.jsonl` 中 07:30:04 的自动运行记录显示，天气描述为英文原句：

> "Patchy rain nearby，21°C，湿度85%，风速8km/h（数据源 wttr.in）"

原因：v0.2 的中英映射表是枚举式的，wttr.in 对"可能有雨"还有变体写法（patchy rain **nearby** / patchy light rain / light rain shower 等），没有命中就按设计回退为原文输出。**枚举式映射永远追不完天气变体**——这是设计层面的教训，不能靠再补几条解决。

**依据二 · 用户反馈**：第 1 批 2 位用户（U01 吴慧君、U02 林思敏）独立给出同向意见：

> U01："内容偏事务提醒，缺少生活、校园资讯类拓展内容"
> U02："只有学业提醒，缺少校园消息、生活小贴士类内容"

2/2 同向，构成明确的需求信号（证据截图见 `screenshots/feedback_U01/U02`）。

## 改动内容

### 1. 天气翻译从"单级枚举"升级为"三级降级"

```
v0.2:  WEATHER_CN.get(desc_en, desc_en)            # 查不到就显示英文
v0.3:  精确匹配(26条) → 关键词兜底(10组) → 原文+显式标记   # 尽量译出，译不出也让你看得出来
```

关键设计：兜底命中不了时**不是悄悄显示英文**，而是附上 `（原文: xxx）` 标记——
- 用户能看懂"这是没翻译的天气描述"
- 日志里能统计翻译盲区，为后续补全映射表提供依据

同时把映射表从 17 条扩到 26 条（补齐 wttr.in 常见的 rain/shower/drizzle 变体）。

### 2. 新增「校园资讯 & 生活贴士」板块

- 新增 `data/tips.csv` 内容池（类型 + 内容两列，首批 12 条）
- 取数逻辑：按**一年中的日序**做轮换，每天取 3 条——同一天内容固定（可复查）、每天自动更换（无需维护）
- 该板块不依赖任何外部 API，断网不影响
- 内容池刻意保持"通用校园生活提示"性质，用户（我）可随时往 CSV 里加真实校园信息

### 3. 版本与留痕同步

- `VERSION` → v0.3（页脚可见）
- 本文件 + `VERSION_HISTORY.md` 更新
- Git commit（待推送）

## 复盘

1. **枚举式映射的局限**：靠"再补一条"永远追不完外部数据源的变化，降级机制（精确→关键词→标记原文）比穷举更可维护。
2. **用户反馈的作用**：2 位用户同向意见比 8 位各说一句"挺好"更有行动价值——这决定了 v0.3 的优先级排序（资讯板块 > 其他候选改动）。
3. **不破坏日志连续性**：改版当天的两次运行（v0.2 / v0.3）都如实留在日志里，7 天记录不受影响。
