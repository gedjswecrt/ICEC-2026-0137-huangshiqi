## 改动内容

本次范围**只限界面层**，共 4 项，不动任何数据与业务流程。

### 1. 页面配色重做（对应 U05）

| 项目 | v0.4 | v0.5 |
|---|---|---|
| 主色 | #1a5fb4（偏亮的蓝） | #0b3d75（深学院蓝），标题/链接统一 |
| 卡片 | 浅灰底 #f6f8fa，无边框 | 白底 + 1px 描边 + 极轻投影，层次更清楚 |
| 页头 | 一行标题 + 细下划线 | 深蓝渐变横幅（#0d4a9e → #062a5a，圆角 + 投影） |
| 正文 | 无背景色 | 浅蓝灰底 #eef2f7，卡片浮起来 |

### 2. 加学校校徽（对应 U05）

- 校徽取自学校官网页头 logo（390×62 PNG），存 `src/assets/logo.png`
- **以 base64 内嵌进 HTML**，不引用外链：早报是单个 HTML 文件，转发到群里、断网打开都能显示校徽
- 校徽原图为白色字 + 透明底，放在深蓝横幅上才清晰——这也是把页头做成深色横幅的直接原因
- 图片缺失时不影响生成（`logo_data_uri()` 捕获异常返回空，只是不显示）

### 3. 手机端适配（对应 U04）

- 补 `<meta name="viewport" content="width=device-width,initial-scale=1">`：此前没有这一行，手机浏览器会按桌面宽度缩放，字小到要看不清
- 加 `@media (max-width:480px)` 断点：缩小边距、字号、卡片内间距，课表时间列收窄到 82px，避免课程名被挤断行

### 4. 深色模式（对应 U04）

- 颜色全部改为 CSS 变量（`--bg / --card / --text / --muted / --brand / --line / --urgent`）
- 用 `@media (prefers-color-scheme: dark)` 跟随系统：系统切深色，早报自动变暗底浅字，无需手动开关
- 深色下主色提亮为 #7fb2ea（深蓝在白字上会糊成一团）

### 5. 新增「今日一句话」摘要（对应 U04 的方向性建议）

莫佳晨提出长期方向："升级为个人智能助理（打开即知今天做什么、明天准备什么）"。这一版取其**最小可用形态**——页头下方一行自动生成的摘要：

> 🎯 今天的课已经上完了；最紧的是《英语Unit8 Lesson1 课前单词预习（23:00截止）》，今天截止。

生成规则（全部由当天数据实时拼出，无任何写死文案）：

| 当前时间 | 课程部分输出 |
|---|---|
| 正在某节课时段内 | 正在上《课程》（地点，HH:MM 下课） |
| 今天还有未开始的课 | 下一节《课程》HH:MM 开始（地点） |
| 今天的课已全部结束 | 今天的课已经上完了 |
| 今天没有课 | 今天没有课 |

后半句取最近一项 DDL：0 天→今天截止、1 天→明天截止、N 天→还剩 N 天；无临近 DDL 则输出"近 7 天没有 DDL"。任一部分解析失败都不影响早报生成。

### 6. 修复一个潜伏的日期计算 bug

写摘要时发现数字不对：11-19 的考试在 11-17 晚间运行时被写成"明天截止"，而实际是 2 天后。

**原因**：剩余天数 = `截止日期 00:00 − 当前时刻 22:00`，差值 1.08 天，`.days` 取整得 1 —— 从 v0.1 起，凡是晚间运行（含每天 07:30 之前的凌晨补跑、以及任何手动验证），每条 DDL 的剩余天数都比实际少半天：

- "今天截止"的条目被算成 −1 天，**当成已过期直接不显示**（今天这条「英语预习」就长期隐身）
- "后天截止"被写成"明天截止"

**修复**：改用 `today0`（今天零点）参与计算。修复前后同一份数据的对比：

| 项 | 修复前 | 修复后 |
|---|---|---|
| 临近 DDL 条数 | 3 项 | **4 项** |
| 英语预习（11-17） | 被隐藏 | 今天截止 |
| 机器人感知期中（11-19） | 明天截止 ❌ | 还剩 2 天 ✅ |

这个 bug 从 v0.1 存在到 v0.4，四次改版都没被发现，因为白天运行时误差不明显、且没人核对过"少了一条"。

## 未采纳的需求

**U04「调课 / 换课强提醒」——不做。**

三条理由：

1. 学校教务系统不对外开放，没有可稳定抓取的接口，抓不到临时调课
2. 本项目的课表来源是 `data/schedule.csv`（本人手工维护），整学期基本不变；若做"与昨日快照比对"，触发条件几乎永远不成立，等于一段死代码
3. 硬做只能做成"你自己改课表时才提醒"，与用户真正想要的"老师临时通知调课"不是同一件事，属于**假实现**——宁可如实不写

替代方案：README 中说明"临时调课以老师/班级群通知为准"，并在实时性上不作承诺。

**U04「已完成 / 待办统计」——本轮不做。**

评估理由：

1. 完成度必须有"哪项做完了"这个输入，而它只能靠人工勾选——本质是把早报扩成任务管理工具，与"每天早上看一眼"的定位有偏差
2. 一旦引入状态列，`ddl.csv` 就从"抄一遍作业清单"变成"每天要维护的表格"，维护成本上升，而收益只有一行百分比
3. 当前 DDL 条目本身数量少（4~5 条），一眼能看完，统计的边际价值低

记录在此，若后续使用中发现"条目多到看不过来"，再作为候选需求重新评估。

## 复盘

1. **反馈分层处理**：U04 的 5 条意见混着界面层（手机端/深色）、功能层（统计）、方向层（个人助理）和不可行项（调课提醒）。一次只做同层改动，界面层的 4 条互不冲突、可一次验证；混着改容易一处出错牵连全局。
2. **一个需求被判定"不做"，比做一个假功能更有价值**：调课提醒看着诱人，但没有数据源，做出来只是个摆设。把判断依据写进记录，比交付一个空壳诚实。
3. **单文件自包含的取舍**：内嵌校徽让 HTML 从 4KB 涨到 67KB。代价是文件变大，收益是转发/离线都能正常显示，对一个"发到班级群"的工具来说，收益更大。
