# 用户反馈采集方案（项目四 · 15 分项）

> 考核原文：③ 完整源码与 **8 位真实用户使用反馈**（15分）
> 未要求"同一时期"，因此采用**分批采集 + 前后对比**方式，兼作迭代依据。

## 一、分批策略（推荐）

| 批次 | 时间 | 人数 | 看的版本 | 目的 |
|---|---|---|---|---|
| 第 1 批 | 11/15 ~ 11/16 | 2 ~ 3 人 | v0.2（当前版） | 拿到最原始的吐槽，找出真问题 |
| 迭代 | 11/17 ~ 11/18 | — | v0.3 | 按第 1 批反馈改（这是迭代 3 的依据） |
| 第 2 批 | 11/19 ~ 11/21 | 5 ~ 6 人 | v0.3（改进版） | 验证改进是否有效 + 凑满 8 人 |

**为什么要分批**：
1. 一次性拉 8 个人看同一版，看起来像"为了凑数"；分批才像真实推广过程
2. 考核另一项要求"至少 3 次基于日志的迭代"——第 1 批反馈正好喂给迭代 3
3. 新旧版本有对比，能写出"改进前后用户评价变化"，这段是加分点

## 二、采集模板（每位用户一行，填写 data/feedback.csv）

| 字段 | 说明 |
|---|---|
| 编号 | U01 ~ U08 |
| 用户标识 | 姓名或"同学A"（征得同意再用真名） |
| 采集日期 | 例：2026-11-15 |
| 使用版本 | v0.2 / v0.3 |
| 使用天数 | 看了几天（1 天也算，如实写） |
| 最有用的板块 | 天气 / 课程 / DDL / 其他 |
| 最想改的地方 | 原话照抄，别润色 |
| 是否继续用 | 会 / 不会 / 看情况 |
| 证据 | 聊天截图文件名，放 screenshots/ |

## 三、提问话术（照念即可，30 秒完成）

> "我在做个每天早上自动生成校园早报的小工具，今天天气 + 今天哪几节课在哪 + 最近什么作业要交。
> 帮我用两天，两句话就行：① 你觉得哪块最有用？② 哪块最想让我改？"

避免问"你觉得好不好用"——这种问题只会得到"挺好的"，没有信息量。

## 四、证据留存（重要）

每位用户至少留一样：
- 微信/QQ 聊天截图（对方评价的原话）→ 存 `02-20Days-Challenge/screenshots/feedback_U01.png`
- 或问卷截图
- 截图里保留时间戳（微信天然带时间），这是"真实性"的最好证明

## 五、8 人不够怎么办

优先顺序：室友 → 同班同学 → 同专业其他班 → 社团/宿舍群。
实在不够，可以放宽到"其他专业同学"，但**必须真的用过**、能说出一句具体评价。
